# Data Collection & Web Scraping
requests==2.32.5        # verified 2026-07-27
# requests picks its charset backend at import time: it prefers
# charset-normalizer (pulled in as a requests dependency, 3.4.x — inside the
# range requests 2.32.5 supports) and only falls back to `chardet` if that
# package also happens to be importable. A stray standalone `chardet` 7.x
# (nothing in this project depends on it) is outside requests 2.32.5's
# hard-coded "chardet < 6" check and makes every `import requests` print
# `RequestsDependencyWarning: ... chardet ... doesn't match a supported
# version`. It is only a warning — decoding still works via
# charset-normalizer — but keep `chardet` out of the environment so it stays
# quiet. Do NOT add chardet here.
charset-normalizer==3.4.4  # requests' charset backend (also a transitive dep); pinned to keep it the one requests uses
beautifulsoup4==4.14.3  # verified 2026-07-27

brotli==1.1.0           # ADDED 2026-07-29 — real bug found and fixed, see below
# Why brotli is now required, not optional: the scraper's own request headers
# (src/data_collection/network.py::_DEFAULT_HEADERS) advertise
# `Accept-Encoding: gzip, deflate, br`. A single sparing live check against
# CIAN confirmed the server responds with `Content-Encoding: br`
# (Brotli) — but neither `requests` nor `urllib3` can decompress Brotli
# without this package installed. Without it, `response.text` silently
# returns garbled/mojibake bytes instead of raising an error, which anyone
# debugging "the parser finds 0 listings" would very plausibly (and
# incorrectly) blame on stale CSS selectors or anti-bot blocking, when the
# actual cause was a missing dependency for a capability the code already
# claimed to support. Verified live under Python 3.11.9: without brotli
# installed, the response decoded to unreadable binary noise; with it
# installed, the same response decoded to real, readable HTML (which in
# this specific case turned out to be a CAPTCHA challenge page — see
# src/data_collection/README.md "Site-liveness" for that separate,
# unrelated finding).
