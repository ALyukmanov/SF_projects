# Прогноз цен на недвижимость в России

Оценка рыночной стоимости квартир на вторичном рынке Москвы и
Санкт-Петербурга по реальным объявлениям с restate.ru. Пользователь вводит
параметры квартиры (город, площадь, этаж, тип дома) и получает точечную
оценку цены и оценочный диапазон.

**Данные**: 9 720 объявлений после очистки (собрано 9 839), Москва и
Санкт-Петербург, restate.ru, август 2026.

**Процесс**: сбор данных → проверка качества → подготовка признаков →
разбиение на обучающую и тестовую выборку с учётом похожих объявлений →
XGBoost → FastAPI + Streamlit → Docker.

**Результат** (тестовая выборка, 1 948 объектов):

| Метрика | Значение |
|---|---:|
| MAE | 5 012 052 ₽ |
| RMSE | 11 144 284 ₽ |
| R² | 0,731 |
| MAPE | 20,8% |

Снижает ошибку примерно на 40% относительно простого базового варианта
(медианная цена за м² по городу и категории) — таблица ниже.

**Честно**: это цена объявления, а не цена сделки; модель покрывает только
2 города; на двух маленьких категориях (дома, комнаты) модель заведомо менее
надёжна и явно сообщает об этом через API — подробности в разделе
«Ограничения».

## Зачем этот проект

Можно ли по базовым параметрам квартиры (город, площадь, этаж, тип дома,
категория) получить быструю ориентировочную оценку рыночной цены? Учебный
проект, но данные и весь процесс обработки — настоящие, не синтетика.

## Данные

- **Источник**: restate.ru, публичные страницы поиска — HTML-парсинг с
  задержками и повторными попытками. ЦИАН (`src/data_collection/cian_scraper.py`)
  сейчас недоступен из-за CAPTCHA и оставлен в коде как резервный вариант.
- **Масштаб**: 9 839 собранных объявлений → 9 720 после очистки и удаления
  дубликатов — Москва (4 931), Санкт-Петербург (4 789), 7 категорий (студии,
  1–3-комнатные, новостройки, комнаты, дома/коттеджи).
- **Проверки качества**: диапазонные фильтры на площадь/цену/этаж, точное
  удаление дубликатов по URL, отдельное обнаружение похожих объявлений
  (совпадающий адрес+комнаты+этаж, цена и площадь в пределах 2%) — такие
  объявления не удаляются автоматически, а учитываются при разбиении на
  обучающую и тестовую выборку (см. ниже).
- **Известные ограничения выборки**: нет координат/района/расстояния до
  метро; год постройки почти всегда отсутствует на страницах поиска,
  поэтому признак «возраст здания» фактически не несёт сигнала.

Полная схема данных — в [`DATA_CARD.md`](DATA_CARD.md).

## Модель

**Таргет**: логарифм цены `log1p(price)`, обратное преобразование при
инференсе. 9 моделей в сравнении, тюнинг лучших трёх через Optuna по
протоколу обучение → кросс-валидация → выбор → один финальный прогон на
тестовой выборке (тестовые данные ни разу не участвуют в подборе
гиперпараметров).

**Разбиение — не случайное.** 37,5% групп похожих объявлений попадали
одновременно в обучающую и тестовую выборку при обычном случайном
разбиении — модель по сути видела почти тот же объект в обучении, что
завышает метрику. Рабочий вариант — разбиение с учётом таких групп: ни одна
группа не оказывается одновременно в обеих выборках.

**Заполнение пропусков — тоже только по обучающей выборке.** У части
объявлений отсутствуют число комнат/этаж/этажность (структурно — площадка
не публикует эти поля для части категорий, см. ниже). Пропуски заполняются
медианой по городу, посчитанной только на обучающей части после разбиения.

Простые базовые варианты для сравнения:

| Подход | MAE | R² |
|---|---:|---:|
| Глобальная медиана | 12 743 526 ₽ | −0,07 |
| Медиана по городу | 12 458 708 ₽ | −0,07 |
| Цена/м² × площадь (по городу и категории) | 8 310 585 ₽ | 0,46 |
| **Модель (XGBoost)** | **5 012 052 ₽** | **0,73** |

**Где модель ошибается больше всего**: дороже объект — больше абсолютная
ошибка (ожидаемо для правого хвоста распределения цены); категории
«дома/коттеджи» (42 объекта в тесте, R²≈0,22) и «комнаты» (38 объектов,
R²≈−0,80) заметно слабее остальных — структурная причина, не размер
выборки: источник вообще не публикует число комнат для этих категорий (и
этаж с этажностью — для домов), поэтому больше данных это не исправит.
`POST /predict` принимает необязательное поле `property_category`; для этих
двух категорий ответ честно возвращает `prediction_reliability:
"limited_data"`.

Полный разбор метрик и сегментов — [`MODEL_CARD.md`](MODEL_CARD.md).

## Рабочая модель

`models/current_model.json` → tuned XGBoost, обученный на реальных данных.
API и дашборд показывают это честно через `GET /model-info`. Переключение
модели в рабочую — отдельная явная команда, никогда не побочный эффект
обучения:

```bash
python scripts/promote_model.py --candidate models/<artifact>.pkl
```

Перед записью в `current_model.json` скрипт проверяет: версию схемы
признаков, точный список и порядок признаков, адекватность метрик,
отсутствие абсолютных путей в метаданных, что заполнение пропусков обучено
только на train-части — и отказывается писать что-либо, если хоть одна
проверка не прошла.

**Откат**: предыдущий артефакт не удаляется при переключении
(`current_model.json` хранит `previous_current_filename`). Откат — та же
команда с указанием предыдущего файла.

## Архитектура

```
restate.ru → скрейпер → data/raw/restate/*.jsonl
                              │
                              ▼
                  data/interim/restate_<city>_listings.csv
                              │
                очистка данных + макроэкономические признаки
                              │
                              ▼
              data/processed/real_estate_cleaned.csv
                              │
              разбиение с учётом похожих объявлений → train/test
                              │
      заполнение пропусков (только по train) → подготовка признаков
                              │
                    подбор гиперпараметров (train/CV only) → XGBoost
                              │
              scripts/promote_model.py (явная, отдельная команда)
                              │
                              ▼
                     models/current_model.json
                              │
                  ┌───────────┴────────────┐
                  │                        │
           FastAPI (:8000)         Streamlit (:8501)
```

`Predictor` переключается в демо-режим на эвристических ценах, если в
`models/` нет обученной модели.

## Быстрый запуск

```bash
cd projects/real-estate-price-prediction
python -m venv .venv && .venv\Scripts\activate   # Windows; source .venv/bin/activate — macOS/Linux
pip install -r requirements.txt -r requirements-dev.txt
```

### API и дашборд

```bash
uvicorn api.main:app --reload --host 0.0.0.0 --port 8000   # http://localhost:8000/docs
streamlit run dashboard/app.py                               # http://localhost:8501
```

`GET /model-info` — метаданные текущей рабочей модели: реальные данные или
демо, источник, метрики, версия схемы признаков.

### Docker

```bash
docker compose up -d
```

Рабочая модель уже входит в клонированный репозиторий, поэтому
`docker compose up` сразу обслуживает обученную модель без ручных шагов.

### Тесты

```bash
pytest tests/ -q
```

### Обучение с нуля

Требует уже собранных данных в `data/interim/` (не публикуются в git —
соберите скрейпером или используйте свои):

```bash
python -m src.data_collection scrape --source restate --city moscow
python scripts/run_feature_engineering_real.py
python scripts/run_model_training_real.py --model xgboost --split-strategy group --params-from-study xgboost
```

Обучение без реальных данных — только с явным флагом (`--allow-synthetic` /
`make train-demo`), иначе скрипты отказывают.

## Ограничения

- **Только 2 города** реально покрыты данными.
- **Нет геопризнаков** — координаты, район, расстояние до метро отсутствуют
  в источнике.
- **Возраст здания и макропоказатели** на реальных данных почти не
  варьируются: год постройки почти всегда отсутствует в источнике.
- **Категории «дома/коттеджи» (42 объекта) и «комнаты» (38 объектов)** —
  структурно слабее: источник не публикует число комнат для этих категорий
  (и этаж/этажность — для домов). Раскрывается через `prediction_reliability`
  в ответе `/predict`.
- **Прогноз — это цена объявления, а не независимая рыночная оценка**:
  модель учится на заявленных продавцами ценах, а не на цене сделки.
