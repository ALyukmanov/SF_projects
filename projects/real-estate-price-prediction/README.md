# Прогноз цен на недвижимость

Оценка рыночной стоимости квартир на вторичном рынке Москвы и
Санкт-Петербурга по реальным объявлениям с restate.ru. Пользователь вводит
параметры квартиры (город, площадь, этаж, тип дома) и получает точечную
оценку цены и примерный диапазон.

Учебный проект, но данные и вся обработка настоящие, не синтетика.

## Данные

- **Источник**: restate.ru, публичные страницы поиска — HTML-парсинг с
  задержками и повторными попытками. ЦИАН (`src/data_collection/cian_scraper.py`)
  раньше был основным источником, сейчас недоступен из-за CAPTCHA и оставлен
  в коде как резервный.
- **Объём**: собрано 9 839 объявлений (24–25 августа 2026), после очистки и
  удаления дубликатов — **9 720 строк**: Москва (4 931), Санкт-Петербург
  (4 789), 7 категорий (студии, 1–3-комнатные, новостройки, комнаты,
  дома/коттеджи).
- **Координаты**: страница поиска даёт только город, но у каждого объявления
  есть своя страница с точкой на карте (`data-lat`/`data-lng`).
  `scripts/enrich_coordinates.py` обходит их по одной с задержкой и кэшем —
  координаты есть у 9 070 объявлений (92%), остальные остаются в выборке с
  признаком `has_coordinates = 0`.
- **Инфраструктура (OpenStreetMap)**: `scripts/prepare_osm_poi.py` берёт
  экстракты Geofabrik по Центральному и Северо-Западному ФО, разбирает их
  через `pyrosm` и собирает `data/external/osm_poi.csv` — 27 539 объектов
  семи типов (метро, ж/д станции, школы, детсады, поликлиники/больницы,
  супермаркеты, парки). Данные © OpenStreetMap contributors, ODbL.
- **Очистка**: диапазонные фильтры по площади/цене/этажу, удаление точных
  дубликатов по URL, отдельно — поиск похожих объявлений (совпадает
  адрес + комнаты + этаж, цена и площадь в пределах 2%). Похожие объявления
  не удаляются автоматически, но учитываются при разбиении на train/test.

Подробнее о данных — в [`DATA_CARD.md`](DATA_CARD.md).

## Что сделано

1. Сбор реальных объявлений скрейпером (restate.ru).
2. Очистка, проверка схемы, обработка пропусков и дубликатов.
3. Геокодирование объявлений и подготовка инфраструктурных объектов из OSM.
4. Геопризнаки: расстояния до ближайших объектов и их количество в радиусе.
5. Разбиение train/test по домам, чтобы объявления одного дома не попадали
   в обе выборки.
6. Обучение XGBoost, подбор гиперпараметров по кросс-валидации, сравнение с
   базовыми вариантами и с моделью без геопризнаков.
7. FastAPI + Streamlit-дашборд, запуск через Docker.

## Геопризнаки (OpenStreetMap)

По координатам объявления и объектам из `data/external/osm_poi.csv`
считаются 18 признаков (`src/features/geo_features.py`):

- расстояние до ближайшего объекта каждого типа — метро, ж/д станция,
  школа, детсад, поликлиника, супермаркет, парк — по формуле гаверсинуса
  (`BallTree`, метрика `haversine`), а не по разнице градусов;
- количество объектов в радиусе 500 м и 1000 м для супермаркетов, школ,
  детсадов, поликлиник, парков и станций метро;
- флаг `has_coordinates`.

Категория `metro` в OSM смешивает станции и входы (~1556 объектов в Москве
на ~260 станций), поэтому каждая категория пространственно схлопывается до
объектного уровня: 371 станция метро в Москве, 83 — в Санкт-Петербурге.

POI ищутся только внутри своего города. Сырые `latitude`/`longitude` в
модель не входят — только 18 производных признаков. Объявления без
координат сохраняются: расстояния — заглушка, счётчики — 0,
`has_coordinates = 0`.

Таблица OSM POI — это внешний справочник: на объявлениях ничего не
обучается, поэтому джойн можно делать до разбиения без риска утечки.

## Разбиение по домам

Координаты получаются на уровне адреса, поэтому многие объявления в одном
доме имеют одну и ту же точку. Если разводить только повторные публикации
одного объявления, разные квартиры одного дома всё равно могут попасть по
обе стороны разбиения — и модель частично «узнаёт» дом.

Поэтому основное разбиение — **по домам** (`build_location_groups` в
`src/data/schema.py`): все объявления с одной округлённой координатой (или
взаимно похожие) идут в одну выборку. 9 720 объявлений → 2 609 «домов».

- **DEV (80%, 7 869 объявлений)** — 4-fold GroupKFold для подбора
  гиперпараметров.
- **HOLDOUT (20%, 1 851 объявление)** — одна финальная оценка, в подборе
  гиперпараметров не участвует.
- Seed 42, одно и то же разбиение для всех вариантов модели.

Проверка `scripts/verify_split_leakage.py`: ни одна группа похожих
объявлений и ни один «домовой» кластер не попадают одновременно в train и
holdout.

Заполнение пропусков (`rooms`, `floor`, `floors_total`) — медианой по
городу, посчитанной **только по обучающей части** после разбиения. Общая
последовательность: разбить → обучить преобразования на train → применить
к train и holdout → обучить модель → оценить на holdout.

## Модель

XGBoost, таргет — `log1p(price)` с обратным преобразованием при инференсе.
Гиперпараметры подобраны через Optuna по кросс-валидации на DEV; holdout не
трогается. 45 признаков: 27 базовых (площадь, этаж, комнаты, тип дома,
город, макропоказатели) + 18 геопризнаков.

Из-за разбиения по домам метрики ниже, чем при случайном разбиении, но
лучше отражают качество на новых объектах: при обычном случайном разбиении
соседи по дому оказываются и в train, и в test, и модель выглядит точнее,
чем она есть.

## Результаты

Финальный holdout (1 851 объявление, разбиение по домам):

| Вариант | MAE | RMSE | R² | MAPE |
|---|---:|---:|---:|---:|
| XGBoost без geo | 6 519 591 ₽ | 11 555 010 ₽ | 0,641 | 26,8% |
| **XGBoost + geo** | **5 909 113 ₽** | **10 198 551 ₽** | **0,720** | **23,8%** |

Геопризнаки дают −9,4% MAE и +0,08 к R². Из 15 самых важных признаков
(permutation importance) 6 — геопризнаки; расстояние до метро — 4-е по
важности.

Сравнение с базовыми вариантами (тот же holdout, статистики только по
train):

| Подход | MAE | R² |
|---|---:|---:|
| Медиана цены по городу | 12 443 032 ₽ | −0,11 |
| Цена/м² по городу и категории × площадь | 7 827 916 ₽ | 0,54 |
| **XGBoost + geo** | **5 909 113 ₽** | **0,72** |

Модель ниже лучшего простого базового варианта примерно на 24,5%.

Где ошибок больше: дорогие объекты (верхняя ценовая треть — MAE ≈ 11,3 млн ₽
против ≈ 2,4 млн ₽ у нижней); категории «дома/коттеджи» и «комнаты»
(~40 объектов на holdout) — источник не публикует для них число комнат и
этаж, поэтому `POST /predict` возвращает для них
`prediction_reliability: "limited_data"`.

Разбор метрик по сегментам — в [`MODEL_CARD.md`](MODEL_CARD.md).

## Запуск

Рабочая модель (`models/xgboost_20260909_112549.pkl`) и таблица OSM POI
(`data/external/osm_poi.csv`, ~2 МБ) уже в репозитории — после `git clone`
данные готовить не нужно. Если `osm_poi.csv` удалить, API вернёт 503, а
дашборд — сообщение (геопризнаки без этого файла не посчитать).

Windows / PowerShell:

```powershell
cd projects\real-estate-price-prediction
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt -r requirements-dev.txt
```

macOS / Linux — то же, но `python3 -m venv .venv && source .venv/bin/activate`.

### API

```powershell
uvicorn api.main:app --reload --port 8000
```

- `http://localhost:8000/docs` — Swagger
- `GET /health`, `GET /model-info` — состояние и метаданные модели
- `POST /predict` — оценка; `latitude`/`longitude` необязательны (без них
  прогноз считается без геопризнаков)

### Дашборд

```powershell
streamlit run dashboard/app.py    # http://localhost:8501
```

### Тесты

```powershell
pytest -q
ruff check .
```

### Docker

```powershell
docker compose up -d    # API :8000 + дашборд :8501
```

### Обучение с нуля

Требует собранных данных в `data/interim/` (в git не публикуются —
соберите скрейпером):

```bash
python -m src.data_collection scrape --source restate --city moscow
python scripts/enrich_coordinates.py
python scripts/prepare_osm_poi.py
python scripts/run_feature_engineering_real.py
```

(демо-режим).

```
real-estate-price-prediction/
├── api/                 # FastAPI: /health, /predict, /model-info, /cities
├── dashboard/app.py     # Streamlit
├── notebooks/           # EDA и статистический анализ (демонстрация методологии)

│   └── external/                    # osm_poi.csv в git (~2 МБ); PBF-экстракты — нет
├── models/              # обученная модель + current_model.json
├── scripts/             # сбор координат, подготовка OSM, признаки, обучение, сравнения
├── src/
│   ├── data/            # схема данных, разбиение по похожим объявлениям и по домам
│   ├── data_collection/ # restate.py (активный), cian_*.py (резервный)
│   ├── features/        # feature_engineering.py, geo_features.py
│   ├── inference/       # predictor.py — инференс для API и дашборда
│   ├── models/          # trainer.py, evaluator.py
│   └── preprocessing/   # cleaner.py, economic_features.py, imputer.py
└── tests/
```

`current_model.json` указывает, какой файл модели загружать. Если обученной
модели нет, `Predictor` работает в демо-режиме на простых эвристиках.

## Ограничения

- **Только 2 города** (Москва, Санкт-Петербург) — только для них есть OSM POI.
- **~8% объявлений без координат**: у них геопризнаки — заглушка. На этой
  подвыборке средняя ошибка выше (хвост на ~160 объектах holdout), хотя
  медианная ошибка и MAPE лучше.
- **Координаты на уровне адреса**: объявления в одном доме имеют одну точку;
  честная оценка — по разбиению по домам.
- **«Дома/коттеджи» и «комнаты»** — маленькие структурно слабые сегменты:
  источник не публикует число комнат (и этаж/этажность — для домов). API
  помечает их `prediction_reliability: "limited_data"`.
- **Дорогие объекты**: абсолютная ошибка заметно выше.
- **Геопризнаки при инференсе** зависят от `data/external/osm_poi.csv` и
  актуальности снимка OSM (снимок зафиксирован в метаданных модели).
- **Возраст здания и макропоказатели** почти не варьируются: год постройки
  почти всегда отсутствует в источнике.
- **Прогноз — это цена объявления, а не цена сделки**: модель учится на
  ценах, которые выставили продавцы.
