# Классификация качества вина (подбор ядра SVM)

Pet-проект: сенсорная оценка `quality` из датасета UCI по красному вину
переводится в бинарную метку «хорошее» / «плохое», сравниваются ядра SVM
(`linear`, `rbf`, `poly`, `sigmoid`) внутри Pipeline `StandardScaler` + `SVC`,
лучшая конфигурация выбирается через `GridSearchCV` с 5-фолдовой
стратифицированной кросс-валидацией.

## Задача

Можно ли предсказать уровень качества вина (хорошее/плохое) только по
физико-химическим показателям (кислотность, сахар, диоксид серы, спирт и
т.д.), и какое ядро SVM лучше всего разделяет два класса на этом датасете?
Это классическое учебное упражнение на подбор ядра и гигиену пайплайна, а не
рекомендация для продакшна.

## Данные

`data/winequality-red.csv` — публичный датасет UCI/Kaggle «Red Wine Quality»
(Cortez и др., 2009), 1 599 строк, разделитель `;`, 11 физико-химических
признаков и целочисленная оценка `quality` (3–8). В отличие от других
проектов портфолио, этот CSV (~84 КБ) хранится прямо в репозитории — см.
[`data/README.md`](data/README.md).

## Что сделано

1. **EDA**: проверка пропусков (нет), дублей строк (240 из 1 599 точных
   дублей), описательные статистики, асимметрия по признакам. Несколько
   признаков сильно скошены (`chlorides`, `residual sugar`, `sulphates`,
   `total sulfur dioxide`, `free sulfur dioxide`), что обосновывает
   масштабирование перед SVM.
2. **Построение таргета**: `quality > 6,5` → «хорошее», `quality < 6,5` →
   «плохое», кодируется `LabelEncoder`.
3. **Подготовка признаков**: четыре дополнительных признака-отношения
   (`free_so2_ratio`, `acidity_ph_ratio`, `citric_volatile_ratio`,
   `sugar_alcohol_ratio`).
4. **Разбиение**: одно стратифицированное разбиение 80/20 (`random_state=42`),
   сохраняющее соотношение классов.
5. **Базовый вариант**: `DummyClassifier(strategy='most_frequent')` —
   учитывая дисбаланс классов, это честная нижняя граница для сравнения с
   SVM, а не accuracy сама по себе.
6. **Подбор модели**: `StandardScaler` + `SVC` в одном Pipeline
   (масштабирование переобучается внутри каждого фолда кросс-валидации, без
   утечки), перебор через `GridSearchCV` по ядрам `linear`/`rbf`/`poly`/`sigmoid`
   с разными `C`, `gamma`, `degree`, `StratifiedKFold(n_splits=5)`,
   критерий отбора — `accuracy`.
7. **Оценка**: лучшая модель оценивается на отложенном тесте (accuracy,
   classification report, confusion matrix), затем перепроверяется финальной
   5-фолдовой стратифицированной `cross_val_score` на полном датасете.

## Результаты

| Метрика | Значение |
|---|---|
| Базовый вариант (по частоте класса), accuracy на тесте | **0,8656** |
| Лучшее ядро / параметры (подбор) | **`rbf`, `C=10`, `gamma=0.1`** |
| Средняя accuracy при подборе (обучающие фолды) | 0,8898 |
| Accuracy лучшей модели на тесте | **0,9156** |
| Прирост относительно базового варианта | +0,0500 |
| Финальная 5-фолдовая CV accuracy (весь датасет) | 0,9031 (± 0,0173) |

Отчёт классификации на тесте (320 строк: 277 «плохое», 43 «хорошее»):

| Класс | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| «плохое» | 0,94 | 0,96 | 0,95 | 277 |
| «хорошее» | 0,72 | 0,60 | 0,66 | 43 |

Лучшее ядро — `rbf`; следующими по качеству в переборе также были `rbf` и
`poly`, `linear` и `sigmoid` отстают.
